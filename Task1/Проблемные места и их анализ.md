## Проблемные места

| Категория            | Описание                                                                                                                             |
|----------------------|--------------------------------------------------------------------------------------------------------------------------------------|
| **Технологии**      | Используются устаревшие решения (например, Microsoft SQL 2008, устаревшая версия Apache Camel), что усложняет интеграции и развитие. |
| **Архитектура DWH** | Все данные сосредоточены в одном хранилище (DWH), что затрудняет масштабирование и добавление новых доменов.                         |
| **Интерфейс**       | Power Builder не адаптируется под новые бизнес-требования, что делает его устаревшим для взаимодействия с данными.                   |
| **Безопасность**    | Хранение всех данных из разных доменов в одном месте создает риски для безопасности.                                                 |
| **Производительность** | Большие объемы данных (сотни терабайт) и сложные трансформации замедляют вывод новых решений на рынок (ttm).                         |
| **Планирование**    | Отсутствует видение архитектурного развития и стратегического планирования.                                                          |


## Приоритизация проблем по MoSCoW

| Приоритет       | Проблема |
|----------------|--------------------------------------------------------------------------------|
| **Must Have**  | ❗ Использование устаревших технологий (Microsoft SQL 2008, устаревшая версия Apache Camel). |
|               | ❗ DWH как единственная точка хранения данных создает проблемы с масштабированием. |
|               | ❗ Большие объемы данных и сложные трансформации замедляют вывод решений на рынок (TtM). |
| **Should Have** | 🔹 Интерфейс Power Builder не масштабируется и не соответствует новым бизнес-требованиям. |
|               | 🔹 Отсутствие видения архитектурного развития мешает долгосрочному планированию. |
| **Could Have**  | 🟡 Все данные из разных доменов хранятся в одном месте, что создает риски безопасности. |
| **Would Like**  | 📝 Документирование новых сервисов, а документирование legacy — на следующих этапах. |
